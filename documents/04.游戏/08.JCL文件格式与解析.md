# JCL 文件格式与解析

## 1. 格式与适用范围

《剑网3》的 `.jcl` 文件是战斗事件日志。正文为逐行记录的文本，每行由六列组成，以制表符分隔；第六列是 Lua 数据表，需要根据事件编号解释其中的字段。读取正文不需要解密，也不需要执行 Lua。

解析时容易出错的地方主要有：Lua 表中的稀疏键、三种不同的时钟、分多次补齐的角色资料，以及事件编号与效果数值标签的区别。本文依次说明这些规则，并给出一份只依赖 Python 3.10+ 标准库的解析器。

字段说明依据固定版本源码、格式资料和四份公开样本。原始资料记录的研究及实测日期为 2026-10-25：四份样本共 107,317 条记录，覆盖已定义的 29 种事件中的 27 种，未出现事件 16、17。这些结果只说明已记录样本的解析情况，不能据此推断所有游戏版本都适用。

表中的“源码定义”表示固定版本源码给出了字段或用途；“样本出现”表示四份文件中出现过该结构。只有源码或旧版资料支持的字段会单独注明，尚未确定的含义保留为未知。字段存在且能够解析，不等于相应游戏机制已经经过受控实验。来源编号对应文末参考资料。

## 2. 六列结构与 Lua 表

### 2.1 字节、行及六列

正文为文本，逻辑上一行一事件。写入时将 Lua 数据中的换行、制表符转义后写入日志；LF 和 CRLF 均应处理。四份样本文件严格 GBK 解码成功、UTF-8 不能解码；不能由 `.jcl` 扩展名断定 UTF-8。示例默认 `utf-8-sig`，读取这四份样本必须指定 `--encoding gbk`；不使用 `errors="ignore"` 或自动替换乱码。

| 列（从 1 起） | Python 下标 | 类型 | 含义与单位 | 证据 |
| --- | ---: | --- | --- | --- |
| 1 | 0 | 十进制整数 | 历史/实现相关校验值，保留原值；不是记录序号 | 源码定义、格式说明及样本 |
| 2 | 1 | 整数 | `GetLogicFrameCount()`，游戏逻辑帧计数 | 源码定义、格式说明及样本 |
| 3 | 2 | 整数 | `GetCurrentTime()`，Unix 秒时间戳 | 源码定义、格式说明及样本 |
| 4 | 3 | 整数 | `GetTime()`，客户端毫秒时钟，不是网络延迟 | 源码定义、格式说明及样本 |
| 5 | 4 | 整数 | 事件编号，源码定义 1–29 | 源码定义、格式说明及样本 |
| 6 | 5 | Lua table 文本 | 事件负载，需递归解析，不能按逗号简单切分 | 源码定义、格式说明及样本 |

使用 `line.split("\t", 5)`，只拆前五个分隔符，再解析第六列。不要对整行使用通用空白 `split()`，它会拆坏名字、消息和空字符串。空行、列数不足、错误编码或截断表应报告行号，不能悄悄丢弃。

第一列的 CRC 在资料中存在版本或说明差异：早期格式说明将它称为废弃字段，但固定版本源码仍执行链式计算，以 0 为初始值，将前一条记录的校验值、当行第 2–6 列文本和内部盐传给 `GetStringCRC`；重放开战前缓存时也会重算此链。[1][WCRC] [7][A1]

本文只解析正文，不实现 CRC 验证，输出中的 `crc_verified` 固定为 `false`。不能直接用 `zlib.crc32` 代替上述算法。文件 SHA-256 只用于核对样本字节，不证明日志真实性。

### 2.2 Lua 表：位置和显式键同时存在

统一使用 `C[n]` 表示外层第 n 列，`P[n]` 表示第六列 Lua 表中的数字键 n，`P[9][13]` 表示嵌套键。Lua 顺序项从 1 开始；结果表和镶嵌表却有合法的显式键 0。

```text
{1001,"示例角色",7,10225,600000,[8]="1234567890123456789"}
```

上式存在键 1、2、3、4、5、8，缺 6、7。不是六元素数组；不得把 GUID 移到装备字段。`{[0]=100,[13]=80,[14]=0}` 也不是从第 0 项开始的密集数组，而是三个带标签的结果项。

解析器需支持嵌套 `{}`、顺序项、`[数字]=值`、`["字符串"]=值`、引号与转义、整数、布尔、nil 和空表；字符串内的逗号、花括号、等号都不是分隔符。不存在、nil、false、0、空字符串、空表必须区分。Lua 执行器会删除值为 nil 的表项；本示例是语法数据读取器，显式 nil 保留为 JSON null，不模拟 Lua 的删键副作用。

本文用 `{"$table": [[key,value], ...]}` 表示任意 Lua 表，保留键的类型、出现顺序、重复键及显式 nil。数字键 1 与字符串键 `"1"` 不混淆；数学上为整数的数字键 `1.0` 归为 1。辅助 `fields` 只投影已知数字键，重复键取末次；完整信息仍在 `payload` 和 `raw_line`。后者保留解码后的原行，不包含行终止符/BOM，因此不承诺 JSON 能逐字节还原原文件。

## 3. 事件字段字典

除特别标注外，下表位置都指 `P` 的一基数字键，类型 `i`=整数、`n`=数值、`s`=字符串、`b`=布尔、`t`=Lua 表；`b/i` 表示来源使用布尔语义但实物可能为 0/1。ID 的数值只作标识。坐标、朝向按游戏原生单位保留，本文没有证实米制或角度制。例值若出现，均为人工示意，不用于确定枚举范围。

下列事件的基本字段来自写入定义。[1][W] 装备、战斗标识和效果结果的补充来源在对应段落注明。

“可缺”不仅指版本变更：源 API 为 nil 时，序列化也可能省掉该键；解析器不强制所有已知项必有、不把缺项补零。所有已见顶层键都列在下表；未来多出的键继续留在原始负载。

装分、装备、奇穴、镇派分别通过回调补齐，每次返回都写一条事件 4。四份样本共有 2,186 条事件 4，其中键 5 出现 2,163 次、键 6 出现 1,625 次、键 7 出现 1,063 次、键 9 出现 647 次。这些记录分多轮补充资料，不应当作相互覆盖的完整快照。用同 ID 的已出现字段更新索引，缺项不擦除旧字段；做某时刻复盘仍应查当时的原事件，不使用未来信息覆盖历史。

装备 `P[6][条目键] = E`。固定版本源码采用八项结构，样本中的 28,868 件装备记录也全部为八项。装备列表的排列位置不是插槽号，真正插槽在 `E[1]`。

| E 位置 | 类型 | 含义 | 说明/证据 |
| --- | --- | --- | --- |
| 1 | i | `nEquipIndex`，装备栏索引 | 源码定义及样本；部分枚举见下表，仍需匹配游戏版本 |
| 2 | i | `dwTabType`，物品表类别 | 源码定义及样本；需与 E[3] 联合查装备 |
| 3 | i | `dwTabIndex`，该表中的物品 ID | 源码定义及样本；不是图标 ID |
| 4 | i | `nStrengthLevel`，精炼等级 | 源码定义及样本；不是装备品质 |
| 5 | t | `aSlotItem`，镶嵌内容 | 稀疏孔位映射，必须保留键 0，源码定义及样本 |
| 6 | i | `dwPermanentEnchantID`，永久附魔 ID | 源码定义；样本中存在该位置，不凭数值推断大小附魔 |
| 7 | i | `dwTemporaryEnchantID`，临时附魔 ID | 源码定义；0 仍是原始值 |

镶嵌 `E[5][孔位]` 在样本中均为两个元素的表；源码明确键 0 为五彩石，1 起为五行石孔位（样本见 1–3）[4][E]。示意 `{[0]={5,13918},{5,24446}}`：第 0 孔与第 1 孔同时存在，子项分别为 `[dwTabType,dwTabIndex]`，即物品表类别和物品 ID。24446 是物品 ID，不是石头等级；从 ID 得到品级/属性仍需匹配版本的物品字典。本程序完整保留子表。旧版资料还记录了附魔位置不同的九项装备布局，但缺少对应样本。[8][A2] 因此示例只为各来源一致的前五项添加字段名。第六至八项应在确认文件版本后按上表解释，不跨版本套用。

奇穴 `P[7][层/条目键] = {nIndex,dwSkillID,dwSkillLevel}`：分别为同层选择索引、技能 ID、等级，三项均有源码定义，不能将 `nIndex` 当技能 ID。镇派 `P[9]` 为技能 ID → 等级映射，零等级不写入；不支持镇派的环境返回空表，样本 647 条镇派表也全为空，不能据此声称验证了非空镇派数据。

## 4. 时间轴与统计口径

### 4.1 时钟、战斗边界与文件名

- 局部时间轴：选定起点后的 `C[4] - start_client_ms`。`C[3]` 用来确定日历时间，但只有秒精度，不能把它乘 1000 当精确技能先后时间；`C[2]` 是另一条逻辑帧轴。相同时间戳按原文件顺序保留，不自行重排或去重。
- Buff 期限：事件 13 的 `P[7]` 是预计结束的绝对逻辑帧，`P[12]` 是剩余帧候选，不是毫秒。帧差换算需已确认的该客户端 `GAME_FPS`；时间换算使用该变量 [2][TIME]，本文不凭经验硬编码 16 或渲染帧率。
- 战斗边界：事件 1 的 `fighting` 明确开始/结束，结束记录 `duration_ms` 取自战斗时长，脱战判定有约 5 秒缓冲 [3][F]。写入端会导入开战前约一秒事件，因此首条记录不一定是事件 1，首末事件跨度不等于官方战斗时长。四份样本都只有一条 `fighting=true,duration=0`，没有结束事件，不能据此算出“官方战斗时长”。
- 命名：文件名由时间、地图名/ID、出现次数最多的 NPC 名/模板 ID 组成；最高频 NPC 不一定是真实首领。用户改名、工具加前缀、样本匿名文件名都不影响行解析。地图优先使用存在的事件 1 `P[4]`；缺失时可将文件名作为带来源标记的辅助信息，不强制按 `split('-')[6]` 定位。
- 不同 ID：运行期角色 `dwID`、跨服 GUID、NPC 模板 ID、地图 ID、装备表 ID、技能/Buff ID 属于不同空间。GUID 保留字符串，大整数不要经过 JavaScript `Number`。交互物件与角色 ID 可能冲突，实体索引至少使用 `player:/npc:/doodad:` 前缀。

JX3DAT 是另一种整体 Lua 数据结构，使用 `return {...}` 和全局缓存，不能按 JCL 的逐行六列格式读取。两者的事件编号也不同：JX3DAT 的技能效果和 Buff 分别对应 1、5，JCL 则对应 21、13。给 JCL 第六列加上 `return`，也不会使它变成 JX3DAT。[6][B]

### 4.2 解析与实体关联

```text
原文件字节 + 指定编码
  → 按 LF/CRLF 取物理行，记录行号
  → 前五列整数 + 第六列完整 Lua 数据文本
  → 递归数据解析：显式键/顺序项/嵌套表/转义
  → 保留完整 payload；按事件编号投影 fields
  → 玩家/NPC/物件分域建立资料索引，保留每条历史记录
  → 按分析目标选时间区间和统计口径，再计算指标
```

解析阶段保留原始施放者。统计召唤物贡献时，可根据 NPC 的 `dwEmployer` 另加归属字段，但不覆盖原 caster。按“某人的召唤物”之类的名字猜主人，会受到跨服同名、NPC 名中含“的”和资料到达顺序的影响，示例不采用这一规则。

读取结束后，实体索引能关联早于资料记录出现的事件；但 `last_present_fields` 是末次已知字段拼接结果，不是某时刻的完整角色快照。所有原事件和资料行号都保留，支持之后按时间回查；不对未知 ID 造出假玩家。

### 4.3 统计公式与口径

在选定效果事件集及其时间窗口后，令 `R=P[9]`：

```text
总伤害（包含反弹）   = Σ事件 Σk=0..5 R.get(k, 0)
总伤害（不含反弹）   = Σ事件 Σk=0..4 R.get(k, 0)
有效伤害             = Σ事件 R.get(13, 0)
总治疗               = Σ事件 R.get(6, 0)
有效治疗             = Σ事件 R.get(14, 0)
DPS / HPS            = 已明确的伤害量 / 治疗量 ÷ 明确的统计秒数
```

两种总伤害口径相差反弹伤害，选择时需明确统计用途。上述公式只聚合选定事件的数值；客户端面板还可能涉及目标过滤、会心与识破分类、盾归属等处理，因此结果不一定相同。[2][RSTAT]

普通治疗事件 27，以及结果标签中的生命偷取 7、吸取 15/16、吸收 8/9，都应分别核对，不能无条件叠加到治疗标签 6/14。25 的命中日志和 19 的施放日志没有伤害量；把它们当“技能次数”时也须先定义次数是施放、命中还是效果触发。

`总治疗 - 有效治疗` 可作为同一口径下的非有效差额，但不保证每种机制都能直接称为“溢出治疗”；伤害差额也不能全部叫“过量击杀”。把盾化解伤害归到盾提供者，需要跟踪 Buff 或盾状态；事件 21 本身并不直接提供这项归属。RDPS/RHPS、减伤贡献、控制链、死亡原因和首领阶段识别属于进一步模型，需要技能机制、来源归属和战斗窗口，不是新增几个索引就能还原。

### 4.4 外部字典与记录范围

- JCL 可得到运行期玩家/NPC 名，但技能效果名通常不随每条记录给出。效果名应按 `(scheme,id,level)` 查询；仅按数字 ID 查询可能把技能和 Buff 混淆，也可能忽略等级差异。
- 技能、心法和地图名称需要外部字典。[11][DATA] 这些字典会变化，分析结果应注明匹配的游戏版本与数据版本。示例只保留日志中的字段，不联网查询，也不写死当前版本的名称。
- 四份样本均为竞技场日志，不足以验证副本首领、所有游戏分支及旧版装备。日志的记录范围受环境开关、附近/自身相关过滤、可观察实体、事件源和节流影响。“没记录到”不能证明“没发生”。
- 缺失战斗结束、缺资料、未出现的枚举、未知尾项都必须可追溯。未知字段保留并不等于其含义已经解释；原始数据完整读取与机制完整重建是两种覆盖度。

## 5. 独立 Python 解析器

将下面的程序保存为 `jcl_parse.py`，使用 Python 3.10+ 运行，无需安装第三方库。输出结构：`source`（文件身份/编码/CRC 状态）、`event_counts`、`entities`、`events`；每个事件有原始负载、原行、已知字段。`equipment_common` 只额外命名装备前五项，`talents_named` 命名奇穴三项，`result_fields` 命名结果键 0–16。

解析器支持样本使用的 Lua 数据子集，以及有限浮点、单/双引号、常用短转义、十进制字节转义、命名键和分号分隔。支持 UTF-8/BOM、GBK、GB18030，LF/CRLF。不是完整 Lua 语言：不接受 `return`、表达式、函数调用、注释、长括号字符串或未知转义；遇到这些内容明确报错，不求值。十进制转义先组回字节，再按所选编码解码。前五列都必须为整数；内部字段按实际 Lua 类型保留，文档字段类型表用于解释而非强行转换。

文件一次读入、所有事件保存在内存，然后输出一份 JSON，便于研究核对；原始与命名视图重复占空间，不适合直接用于超大文件的流式处理。语法正确但事件字段不足时依然保留，不捏造默认值；语法损坏则整次失败、stderr 含行号、退出码 2，解析完成前不写 stdout。

```python
class LuaTable:
    def __init__(self, entries):
        self.entries = entries

    def get(self, key, default=None):
        # 数字键 1 与字符串键 "1" 不合并；原 entries 也保留重复键。
        for k, value in reversed(self.entries):
            if type(k) is type(key) and k == key:
                return value
        return default


class LuaDataParser:
    number = re.compile(r"[+-]?(?:0[xX][0-9a-fA-F]+|(?:\d+(?:\.\d*)?|\.\d+)(?:[eE][+-]?\d+)?)")
    name = re.compile(r"[A-Za-z_][A-Za-z_0-9]*")

    def __init__(self, text, encoding="utf-8"):
        self.text = text
        self.pos = 0
        self.encoding = codecs.lookup(encoding).name.replace("utf-8-sig", "utf-8")

    def fail(self, message):
        raise ValueError(f"Lua 列 {self.pos + 1}: {message}")

    def space(self):
        while self.pos < len(self.text) and self.text[self.pos].isspace():
            self.pos += 1

    def take(self, token):
        self.space()
        if self.text.startswith(token, self.pos):
            self.pos += len(token)
            return True
        return False

    def need(self, token):
        if not self.take(token):
            self.fail(f"应为 {token!r}")

    def string(self):
        quote = self.text[self.pos]
        self.pos += 1
        result = bytearray()
        escapes = {"a": "\a", "b": "\b", "f": "\f", "n": "\n", "r": "\r",
                   "t": "\t", "v": "\v", "\\": "\\", '"': '"', "'": "'"}
        while self.pos < len(self.text):
            char = self.text[self.pos]
            self.pos += 1
            if char == quote:
                return result.decode(self.encoding)
            if char != "\\":
                result.extend(char.encode(self.encoding))
                continue
            if self.pos == len(self.text):
                self.fail("字符串转义被截断")
            char = self.text[self.pos]
            self.pos += 1
            if char in escapes:
                result.extend(escapes[char].encode(self.encoding))
            elif char.isascii() and char.isdigit():
                digits = char
                while len(digits) < 3 and self.pos < len(self.text) and self.text[self.pos] in "0123456789":
                    digits += self.text[self.pos]
                    self.pos += 1
                if int(digits) > 255:
                    self.fail("十进制转义超出一个字节")
                result.append(int(digits))
            else:
                self.fail(f"不支持的字符串转义 \\{char}")
        self.fail("字符串未闭合")

    def value(self):
        self.space()
        if self.pos == len(self.text):
            self.fail("缺少值")
        if self.text[self.pos] in "\"'":
            return self.string()
        if self.take("{"):
            entries, implicit = [], 1
            while not self.take("}"):
                if self.take("["):
                    key = self.value()
                    if type(key) not in (int, float, str, bool):
                        self.fail("表键必须是标量且不能为 nil")
                    if type(key) is float and key.is_integer():
                        key = int(key)
                    self.need("]")
                    self.need("=")
                else:
                    self.space()
                    start = self.pos
                    match = self.name.match(self.text, self.pos)
                    if match:
                        self.pos = match.end()
                    if match and self.take("="):
                        key = match.group()
                    else:
                        self.pos = start
                        key = implicit
                        implicit += 1
                entries.append((key, self.value()))
                if self.take("}"):
                    break
                if not (self.take(",") or self.take(";")):
                    self.fail("缺少表项分隔符")
            return LuaTable(entries)
        match = self.number.match(self.text, self.pos)
        if match:
            self.pos = match.end()
            token = match.group()
            if "x" in token.lower():
                return int(token, 16)
            if not any(c in token.lower() for c in ".e"):
                return int(token)
            value = float(token)
            if not math.isfinite(value):
                self.fail("非有限数字")
            return value
        match = self.name.match(self.text, self.pos)
        if match and match.group() in ("true", "false", "nil"):
            self.pos = match.end()
            return {"true": True, "false": False, "nil": None}[match.group()]
        self.fail("仅支持 Lua 数据字面量")

    def parse(self):
        value = self.value()
        self.space()
        if self.pos != len(self.text):
            self.fail("表后存在额外内容")
        if not isinstance(value, LuaTable):
            self.fail("JCL 载荷必须为表")
        return value

        fields = named(payload, names)
        event = {"line": lineno, "crc": crc, "frame": frame, "unix_s": unix_s,
                 "client_ms": client_ms, "event_type": event_type, "kind": kind,
                 "fields": fields, "payload": payload, "raw_line": line}
        if event_type == 4:
            equipment = fields.get("equipment")
            if isinstance(equipment, LuaTable):
                # 只解释跨来源一致的前五项；附魔尾部存在版本/文档冲突，留在原表。
                event["equipment_common"] = [
                    {"entry_key": k, "fields": named(v, "slot table_type item_id strength sockets")}
                    for k, v in equipment.entries]
            talents = fields.get("talents")
            if isinstance(talents, LuaTable):
                event["talents_named"] = [
                    {"entry_key": k, "fields": named(v, "index skill_id level")}
                    for k, v in talents.entries]
        if event_type == 21 and isinstance(fields.get("results"), LuaTable):
            results = fields["results"]
            event["result_fields"] = {}
            result_names = {0: "physical", 1: "solar", 2: "neutral", 3: "lunar", 4: "poison",
                            5: "reflected", 6: "heal", 7: "steal_life", 8: "absorb_heal",
                            9: "absorb_damage", 10: "shield_damage", 11: "parry", 12: "insight",
                            13: "effective_damage", 14: "effective_heal",
                            15: "transfer_life", 16: "transfer_mana"}
            for key, value in results.entries:
                if type(key) is int and key in result_names:
                    event["result_fields"][result_names[key]] = value
        if event_type in (4, 8, 12) and type(fields.get("id")) is int:
            entity_kind = {4: "player", 8: "npc", 12: "doodad"}[event_type]
            entity_key = f"{entity_kind}:{fields['id']}"
            entity = entities.setdefault(entity_key, {"record_lines": [], "last_present_fields": {}})
            entity["record_lines"].append(lineno)
            # 缺项不覆盖旧值；显式 nil 仍覆盖。历史事件是时间点真值，末次索引仅便于查找。
            entity["last_present_fields"].update(fields)
        counts[event_type] += 1
        events.append(event)
    return {"source": {"file": path.name, "bytes": len(raw), "sha256": hashlib.sha256(raw).hexdigest(),
                       "encoding": encoding, "crc_verified": False},
            "event_counts": dict(sorted(counts.items())), "entities": entities, "events": events}


def main():
    parser = argparse.ArgumentParser(description=__doc__)
    parser.add_argument("input", type=Path)
    parser.add_argument("--encoding", default="utf-8-sig", help="默认 utf-8-sig；简体客户端样本可指定 gbk")
    args = parser.parse_args()
    try:
        output = parse_file(args.input, args.encoding)
    except (OSError, ValueError, LookupError) as exc:
        parser.exit(2, f"解析失败: {exc}\n")
    # 输出固定 UTF-8 JSON；先完整解析再写出，错误时不会产生半份 JSON。
    encoded = json.dumps(output, ensure_ascii=False, allow_nan=False, default=json_default)
    sys.stdout.buffer.write(encoded.encode("utf-8") + b"\n")


if __name__ == "__main__":
    main()
```

## 6. 运行示例

保存 `jcl_parse.py` 后，使用实际文件路径运行。默认编码是 `utf-8-sig`；GBK 文件需指定 `--encoding gbk`：

```bash
python3 '/实际路径/jcl_parse.py' '/实际路径/战斗.jcl' --encoding gbk > '/实际路径/战斗.json'
```

以下独立命令在当前目录生成两条人工构造的记录，不是真实战斗数据。字符串中的 `\t` 在 Python 执行时变成真实制表符，不要把展示用的反斜杠 t 原封不动复制进 JCL。

```bash
python3 - <<'PY'
from pathlib import Path
rows = [
    '0\t100\t1700000000\t1000\t21\t{1001,2001,0,1,123,1,false,3,{[0]=100,[13]=80,[14]=0}}',
    '0\t101\t1700000000\t1060\t28\t{2001}',
]
Path('example.jcl').write_text('\n'.join(rows) + '\n', encoding='utf-8')
PY
python3 jcl_parse.py example.jcl > example.json
```

输出是完整 JSON，以下是第一条记录的字段视图（省略原始负载、原行、文件哈希等其他部分）：

### 7.3 历史合成用例与复现方法

原始资料还记录了在 Python 3.12 下通过的 37 项合成断言，涉及以下情况。

- 数据结构：嵌套与空表、稀疏键、重复键、数字键 0、数字键与字符串键的区别、显式键不推进顺序项，以及 nil、缺失、false、0、空字符串的区别。
- 字符与文件编码：中文、引号内分隔符、反斜杠、常用转义、UTF-8 与 GBK 十进制字节转义、数字字面量、CRLF、BOM、末行无换行、GBK 与 GB18030。
- 事件处理：事件早于资料、缺项不覆盖已有资料、缺少击杀者、未知事件保留及 CLI JSON 输出。
- 错误输入：截断字符串或表、缺值、缺分隔符、尾随垃圾、函数调用、`return`、nil 表键、非法转义、非有限数、错误编码、空记录、错误列数和非整数头列。CLI 失败时退出码为 2，stdout 为空，stderr 包含行号。

复现真实样本统计时，先从文末的固定版本样本链接下载四份文件，将解析器保存为 `jcl_parse.py`，再修改下方两个路径运行。输出的哈希、事件总数和分布应与前两节一致；脚本只读取本地文件。

```bash

import importlib.util
from pathlib import Path
script = Path('/实际路径/jcl_parse.py')
sample_dir = Path('/实际路径/samples')
spec = importlib.util.spec_from_file_location('jcl_example', script)
module = importlib.util.module_from_spec(spec)
spec.loader.exec_module(module)
for path in sorted(sample_dir.glob('*.jcl')):
    data = module.parse_file(path, 'gbk')
    print(path.name, data['source']['sha256'], len(data['events']), data['event_counts'])
PY
```
